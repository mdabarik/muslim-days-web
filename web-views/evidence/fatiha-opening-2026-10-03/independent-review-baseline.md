# Independent Fatiha opening baseline

Source-first direct PDF1 renders inspected before live webpage screenshots. Scope is the opening only.

The most concrete ordering defect is that original **سورة الفاتحة / সূরা ফাতিহা**, its surah/revelation/ruku/ayah metadata, and then basmala form the opening, whereas the web moves the source header+metadata after all five Quran rows. Its top title instead uses directory labels **আল-ফাতিহা / الفاتحة**. Move the already-transcribed source header before the basmala; do not invent missing title diacritics.

The unnumbered basmala still precedes numbered الحمد in both source and webpage. Its words are not observed to be reordered. The strong visual difference is the Amiri font and reduced green styling versus the original larger purple calligraphy with cyan Bengali line. Typeface, diacritic geometry, ornamental title marks, band geometry, and rosette shapes are not exact copies.

Two first-row body annotations (r0-a9/r0-a10) remain collision-withheld in the current desktop screenshot, although preserved in the detail list. Thus the first row is not fully visibly faithful either.

Current runtime hashes and fresh source/live screenshot references are preserved in the JSON baseline. No implementation changes made by this reviewer; final narrow review pending.
